# SEMI ATLAS — 半導体バリューチェーン

9工程・51社の工程表、工程専用ページ、企業詳細を表示する静的Webアプリです。前工程から後工程を左から右へ配置し、装置・部品・材料メーカーを分類します。企業詳細には財務構成比、製品シェア比較、確認済み適時開示、公式IR資料リンク、関連ニュースを表示します。

## 自動取得と公開

`.github/workflows/daily.yml` をリポジトリの既定ブランチ `main` に配置すると、GitHub Actions が毎日22:00 UTC（翌日07:00日本時間）に情報を取得し、GitHub Pagesに配信します。時刻は予定でありGitHub側の混雑によって遅れることがあります。手動実行にも対応しています。

導入手順：

1. この変更を `main` に取り込みます。
2. GitHubリポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択します。
3. **Actions → Daily data update and Pages → Run workflow** を実行します。
4. 成功した実行の `deploy` ジョブまたは Settings → Pages に表示される公開URLを開きます。現在のローカル作成だけではWebサイトは公開されません。

日次更新はAPIキーや有料ニュース契約を使いません。GitHub ActionsとPagesの無料利用範囲はリポジトリの公開設定・利用プラン・利用量によります。Pagesはアプリを公開するため、非公開情報をJSONに登録しないでください。

取得結果は `site/data/updates.json` に保存し、Actionsのボットが `main` にコミットします。`contents: write` が必要です。ブランチ保護や組織ポリシーでボットによる更新が拒否される場合は、更新方法の調整が必要です。取得失敗を成功扱いせず、画面に状態と最後の成功日時を表示します。全ニュース取得失敗時も前回の情報を保持して配信し、Actionsに警告を残します。コード・ビルド・保存が失敗した場合は公開しません。

## 無料の取得元と範囲

- ニュース：Google NewsのRSS検索。企業名・別名と半導体関連語で検索し、見出しでも企業名と関連語を検証します。直近90日・1社最大12件。見出し・媒体名・日時・リンクだけを保存します。本文の転載、有料記事の本文取得は行いません。リンク先に有料記事が含まれることがあります。Google Newsは無保証のRSSで、形式変更や停止により取得できない場合があります。利用条件は取得元のものに従ってください。
- 公式IR資料：最初は東京エレクトロン、ASML、ニコン、SCREEN、ディスコ、SUMCO、信越化学、レゾナックの8社の公式IR URLを設定しています。各URLのライブ取得はこのクラウドの接続制限により未検証です。公開HTMLから決算等のPDF・日付入り資料リンクを抽出し、同一ホストのIR一覧を最大1ページ追加取得します。JavaScriptのみのサイトや異なるサブドメインの資料は収集できない場合があります。それ以外の未設定企業は公式IR取得元未設定と表示します。
- 適時開示：公式IRの自動収集結果を、正式な適時開示と誤認させないように分けます。正式な適時開示と確認できた資料は `research.json` の `disclosures` に出典付きで登録します。TDnet全件自動取得は未実装です。
- 財務比率：決算資料リンクの発見は自動化しますが、部門数値の抽出・検証は自動反映しません。同じ期間・通貨・会計基準の確認済み数値だけを登録します。未確認と非開示を区別し、全社利益ゼロや赤字時に誤解を招く割合を表示しません。
- 製品シェア：出典のある確認済みデータだけ表示します。同じ製品市場・年・地域・金額／台数の定義を1つの比較にまとめます。有料調査資料の取得・転載は行いません。初期版に確認済みシェア数値はありません。

ニュースの関連性は見出しによる自動判定です。同名企業や引用による誤検出、見出しに製品名がない記事の取りこぼしがあり得ます。確認が必要な情報を判断の根拠とする場合は原文を参照してください。

## 手元で開く

Python 3.12以上・Node.jsが利用できる環境で、依存パッケージのインストールは不要です。

```sh
npm test
npm run build
npm start
```

開発サーバーはポート3000です。

**`site/standalone.html` はダブルクリックで開ける単一HTML版です。** 生成時点のデータを内包しており、ネット接続やサーバーなしで閲覧できます。最新データへの自動更新はGitHub Pages版で行います。Actions実行結果の **Artifacts → semi-atlas-offline** からHTMLのZIPをダウンロードすることもできます。Artifactsの取得にはGitHubログインが必要な場合があります。

```sh
npm run update     # 無料RSS・登録済み公式IRを取得
npm run check      # データの出典・比率・市場構成を検証
npm run build      # 配信用HTMLと単一HTMLを生成
```

収集処理はPython標準ライブラリのみで動作し、TLS検証と既存のプロキシ設定を保持します。四並列・1リクエスト15秒・最大2MB。HTMLの見出しとリンクのみに限定しています。

## データ管理

- `site/data/catalog.json`：企業・別名・製品・工程・公式サイト・IR URL・企業概要・立ち位置・銘柄・拠点情報。初期の製品分類は要確認です。複数分野を扱う企業の分類は主な表示区分を示します。
- `site/data/research.json`：確認済みの財務値・市場シェア・適時開示。
- `site/data/updates.json`：自動取得された見出し・IR資料リンク・取得状態。
- `sources.json`：取得のON/OFF、件数、期間、タイムアウト。

入力例は `docs/data-format.md` を参照してください。市場シェアと財務値は検証処理で出典・期間等を必須にします。定義が違う部門利益を営業利益として登録しないでください。セグメントに非半導体事業が含まれる場合、その全額を半導体事業の値と扱わないでください。初期版では確認済み財務値は未登録です。

公開版は閲覧用です。ブラウザーからの登録・サーバー管理画面・認証はありません。データ編集はGitHub上のJSON編集とコミットで行います。

## この環境での検証制限

Google Newsと公式IRのホストは現在のクラウドネットワークで許可されていません。環境設定の下書きに必要なドメインを追加しましたが、下書き保存だけではランタイムへ反映されません。設定を反映した後に `npm run update` でライブ取得を検証してください。GitHub Actionsはこのクラウドのネットワーク制限とは別の実行環境です。

このタスクでは公開されたWebサイトや稼働中の日次スケジュールの成功を意味しません。公開はGitHubへの反映・Pages設定・Actionsの成功確認後に成立します。

## 企業概要・工場所在地・時価総額

企業詳細に次を追加しています。

- 51社の事業説明、技術分野、バリューチェーン上の役割。
- 上場区分、銘柄・取引所、非上場子会社の所属グループ。
- 代表的な生産・開発拠点（登録済み企業のみ）の国・都市・機能。所在地からGoogle Mapsで検索できます。
- CompaniesMarketCapの無料公開ページを使う日次の時価総額収集。独立上場のない5社は対象外とし、親会社の数値を代用しません。

**概要と拠点は初期編集情報で、公式ページの最新照合は未実施です。** 拠点に「所在地・機能の最新照合待ち」を表示し、工場と未確認の製造拠点候補、研究開発拠点を区別します。情報がない企業には未登録と表示します。順位や市場シェアの数値は概要で推測しません。公式情報の確認先は一般公式サイトであり、照合済みの証拠資料とは区別しています。

時価総額はUSDの参考値です。取得元が明示しない算定基準日は「取得元に明示なし」と表示し、取得日時を株価の算定日時として代用しません。現在の株式時価総額のライブ取得はクラウドの接続制限により未検証です。数値の初期登録はありません。ページの銘柄を正確に照合できない場合、金額が複数ある場合、ページ形式が変わった場合は推定せず失敗扱いにし、前回の数値と成功日時を保持します。資料の単位・通貨が不明な場合も取得しません。

`marketCapSource` の企業ページのslugと取引所付きtickerは初期登録です。一部のslugは取得元に存在しない可能性があるため、日次実行結果を確認してください。時価総額は全社の評価額であり、半導体関連部門の価値ではありません。上場状態の変更は無料データ源の取得だけでは確定できないため、公式IR等で確認して `listing` を更新してください。

`sources.json` の `marketCap.enabled` で取得を停止できます。新しい取得先の `companiesmarketcap.com` をクラウド環境設定の許可ドメインの下書きに追加しました。下書き保存は実行中の接続許可を変更しません。GitHub Actionsからの収集は独立したネットワークで実行されます。

## 工程別ページ

トップページの左から右へ並ぶ工程表から、各工程の専用ページへ移動できます。各工程ページでは、工程の説明とその工程に属する装置・部品・材料メーカーを表示し、その工程内の企業検索・カテゴリー絞り込みに対応します。前後工程へのリンクと全工程へのナビゲーションがあります。

- 工程ページ：`#/stage/wafer`、`#/stage/lithography` など、catalog.jsonの工程IDを使います。
- 工程から企業詳細：`#/company/tel?stage=lithography` のように遷移元工程を保持し、企業詳細の戻るリンクで元工程へ移動できます。
- 企業詳細の工程タグから、該当工程ページへ移動できます。
- 企業検索結果はトップページで検索時に表示します。工程表の企業数は、検索条件ではなくその工程の登録総数です。

GitHub Pagesや単一HTMLで直接リンク・再読み込みに対応するため、工程ごとに固有のハッシュURLを使います。表示上の独立ページであり、HTMLファイルを工程数分コピーする方式ではありません。ページ遷移後も自動取得済みデータの読み直しは不要です。

ダイフクと村田機械は、露光・成膜・エッチング・洗浄・計測検査をつなぐ工場内自動搬送の役割で配置しています。工程の加工装置そのものや特定企業との取引関係を示す分類ではありません。村田機械と村田製作所は別企業です。村田機械は非上場扱いとし、村田製作所の銘柄や時価総額を代用しません。ダイフクの公式IR URLも日次収集対象に追加しました（実取得・最新照合は未検証）。

野村マイクロ・サイエンスと栗田工業は、超純水・水処理という工場インフラの役割で前工程に配置しています。栗田工業は水処理薬品も扱いますが、主な表示区分は設備メーカーです。日本マイクロニクスは既存のID `mjc` を維持して説明を拡充し、日本電子材料（ID `jem`）とともに前工程最後の計測・プローブ検査に表示しています。プローブカードの主用途はウェーハ段階の電気検査であり、最終パッケージ検査のソケットと同じ用途として扱っていません。日本電子材料と日本電子は別企業です。概要と拠点情報の最新照合は未実施です。

プローブテストは前工程を終えたウェーハの電気検査として、ダイシングより前の `inspection`（計測・プローブ検査）に配置します。日本マイクロニクスと日本電子材料は後工程の `test`（最終検査）には配置しません。ウェーハ検査にも用いる半導体試験装置のメーカーは、プローブ検査と最終検査の双方に表示します。

## 半導体メーカー一覧

上部の「工程表」「半導体メーカー」で表示を切り替えます。メーカー一覧（`#/manufacturers`）は企業名・製品・国による検索、事業形態（ファブレス・ファウンドリー・IDM・OSAT）、半導体の種類（ロジック・メモリ・パワー・アナログ・通信／RF・センサー）の複合絞り込みに対応します。OSATは組立・パッケージング・テスト受託企業です。初期登録27社を `catalog.manufacturers` に保存し、種類を複数指定できます。メーカー概要・分類は最新の公式資料との照合待ちです。ファウンドリーとOSATの種類は受託対象を示します。単一HTML版でも同じ機能を利用できます。

メーカー名から `#/manufacturer/<id>` の詳細ページへ移動できます。装置企業と同じ概要・時価総額・拠点・財務・シェア・適時開示・IR・ニュースの項目を表示し、データ未登録は明示します。メーカーの日次自動収集はまだ設定していません。`manufacturingRelationships` に customerId（委託元）・foundryId（製造委託先）・status・sourceUrl・noteを登録します。verifiedにはverifiedAtも必要です。ファウンドリーには受託元、ファブレスには製造委託先を表示します。現在のNVIDIA・AMDとTSMCの関係は一次資料の照合待ちの候補です。
